## 0. 概览

### 0.1 估算前提与符号约定

- **粒度**：单个任务工作量在 0.5–5 人天之间，超过的需进一步拆分；
- **角色代号**：
  - `BE`：后端工程师
  - `FE`：前端工程师
  - `DBA`：数据库（兼）
  - `DevOps`：运维（由开发团队兼）
  - `QA`：测试工程师
  - `PM`：项目经理
  - `Arch`：技术负责人/架构师
  - `UX`：交互/UI 设计
- **任务编号**：`<阶段>-<模块>-<序号>`，例：`I1-CU-003`
- **依赖**：标注前置任务 ID；空表示无前置；
- **关联**：UC = SRS 用例编号；§x.y = DSS 章节；
- **估算**：单位为人天，1 人天 = 8 小时净开发时间，**不含**会议、设计澄清、CR 排队等隐性成本（实际排期建议加 30% buffer）；
- **状态**（执行时填）：TODO / WIP / DONE / BLOCKED。

### 0.2 推荐团队配置（基线）

| 角色 | 人数 | 说明 |
| --- | --- | --- |
| 技术负责人/架构师 | 1 | 兼任后端 |
| 后端工程师 | 2–3 | 含数据库 |
| 前端工程师 | 2 | — |
| 测试工程师 | 1 | 中后期投入 |
| 产品/项目经理 | 1 | — |
| UI 设计 | 0.5 | 阶段性投入 |

### 0.3 阶段与产物总览

| 阶段 | 周期 | 主要产物 | 任务数 | 估算（人天） |
| --- | --- | --- | --- | --- |
| 阶段 0：设计与基础设施 | 2 周 | 详细设计、原型、脚手架、Jenkins 通路 | 18 | 38 |
| 迭代 1：IAM + 客户 + 系统管理 | 3 周 | 用户/角色/部门、客户档案、回收站 | 32 | 70 |
| 迭代 2：合同管理 | 3 周 | 合同档案、附件、变更、提醒 | 24 | 60 |
| 迭代 3：回款 + 通知 | 3 周 | 回款计划、实际回款、核销、通知 | 28 | 70 |
| 迭代 4：看板 + 报表 | 2 周 | 综合看板、回款报表、导出 | 16 | 36 |

### 11.1 通用 DOD（Definition of Done）

每个开发任务必须同时满足以下条件方可标记 DONE：

1. 代码通过 lint + 静态扫描；
2. 提交关联 JIRA-ID，描述清晰；
3. 单元测试覆盖率达标（关键模块 ≥ 80%）；
4. 至少 1 名 Reviewer Code Review 通过；
5. 接口变更已更新 OpenAPI 文档；
6. UI 变更已更新设计稿评审记录；
7. 有数据库变更时已提交 Flyway 脚本（不修改历史脚本）；
8. 在测试环境完成自验收 + 关键链路冒烟。
