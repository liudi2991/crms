## 🎯 适合谁用

中小企业 / 业务团队需要把"客户 → 合同 → 回款 → 核销 → 账龄分析 → 看板"打通的场景。**单机一台 4G 云主机即可承载**。

## ✨ 核心能力

### 业务模块

- **IAM**：5 角色（R01 销售 / R02 销售经理 / R03 财务 / R04 主管 / R05 超管）+ 30+ 权限点，Sa-Token JWT，三档数据范围（ALL / DEPT / SELF）
- **客户档案**：CRUD / 合并去重 / 多联系人 / 变更日志
- **合同管理**：状态机（DRAFT → EFFECTIVE → COMPLETED / TERMINATED / EXPIRED）、附件上传（最多 20 个 / 单个 50MB）、变更记录、到期提醒
- **回款全流程**：计划生成（月 / 季 / 一次性）→ 实际登记 → **自动核销（FIFO）** → 红冲 → 批量导入 → 账龄分析（0-30 / 31-60 / 61-90 / 90+）
- **看板与报表**：KPI 看板、月度趋势、TOP 客户、我的待办、Excel 导出
- **通知中心**：合同到期 / 回款临期 / 回款逾期 站内信
- **系统管理**：参数 / 操作审计 / 硬删除二次密码 / 回收站

### 工程基础设施

- **公共能力**：统一响应 `Result<T>` / 全局异常 / AES-256-GCM 字段加密 / Snowflake ID / 操作日志 AOP / Trace ID 透传
- **数据库**：Flyway V1.0.0–V1.0.6 自动迁移
- **存储**：本地磁盘 / MinIO 双实现，`crms.storage.type` 一键切换
- **密钥管理**：所有敏感参数走 `${VAR:?}` 环境变量，仓库零硬编码

### 部署与运维

| 场景 | 文件 |
| --- | --- |
| 单机部署（推荐个人 / 小团队） | `deploy/docker-compose.single.yml` + `scripts/release.sh` |
| 双副本生产部署 | `deploy/docker-compose.prod.yml` + `deploy/Jenkinsfile` |

| 备份巡检 | `deploy/scripts/{backup,check_app,check_disk}.sh` |

5 分钟从 0 到上线：[`docs/deploy-quickstart.md`](../deploy-quickstart.md)。

## 🧪 自动化验收

`scripts/acceptance.sh` 共 **A–G 7 段、70+ 项检查**：

- A: 冒烟（健康 / 登录 / 字典）
- B: E2E 主流程（客户 → 合同 → 计划 → 核销 → 看板）
- C: 回归（V1.0.5 附件 / V1.0.6 列宽 / UC-04-08 逾期口径）
- D: 权限（RBAC + 数据范围 + 越权）
- E: 算法（FIFO 核销 / 账龄桶 / 红冲反向）
- F: 安全（未授权访问 / SQL 注入探测 / 敏感字段不回显）
- G: 可观测（actuator / openapi / trace id）

## 🛠️ 验收期发现并修复

- **UC-03-05 附件**：上限硬编码 10 → 系统参数默认 20；大文件 `SYS-500` → `FL-003`；新增 MinIO 实现
- **UC-04-08 逾期预警**：看板与列表口径不一致 → VO 层即时计算
- **数据库列宽**：`content_type VARCHAR(64)→VARCHAR(255)`、`error_message VARCHAR(500)→TEXT`
- **前端**：详情页路由响应、并发请求 token、附件预览鉴权、`<el-statistic>` 渲染等共 7 处

详见 [`docs/issues/`](../issues/)。

# 本机开发
git clone https://github.com/liudi2991/crms.git
cd crms
cd deploy && cp .env.example .env  # 编辑填密钥
docker compose -f docker-compose.single.yml up -d
