## 1. 登录与账号

### 1.1 登录

1. 浏览器打开系统地址（开发环境默认 `http://localhost:5173`，生产以管理员告知为准）。
2. 在登录页输入 **用户名** 与 **密码**，点击「登录」。
3. 若提示**首登强制改密**，会跳到「修改密码」页：
   - 旧密码 = 管理员告知的初始密码（如 `Admin@123456`）
   - 新密码：长度 ≥ 8，建议大小写字母 + 数字 + 符号
4. 完成后会自动跳到「综合看板」。

### 1.2 锁定与解锁

- **连续 5 次** 输错密码会被锁定 **15 分钟**（系统默认；管理员可调）。
- 锁定后任由你正确输也进不去，**直接联系系统管理员**到「系统管理 → 用户管理」点 **解锁**，无需等待。

### 1.3 修改密码与退出

- 顶部菜单「账户 → 修改密码」（或地址 `#/system/change-password`）。
- 同样位置有「退出登录」。**长时间未操作会话会过期**，重新登录即可。

### 1.4 我的角色与权限

- 顶部菜单「账户 → 我的信息」可看到：所属部门、当前角色、数据范围（本人 / 本部门 / 全公司）。
- **看不到的菜单 ≠ 系统坏了**，是 RBAC 控制——找管理员申请权限。

## 2. 综合看板

路径：`#/dashboard`（登录默认页）

| 卡片 | 含义 | 数据来源 |
| --- | --- | --- |
| 合同总额 | 在册有效合同金额合计 | `report:dashboard` |
| 已回款 | 累计实际回款（扣红冲） | 同上 |
| 待回款 | 应收账款总额（= 账龄四桶之和） | 同上 |
| 逾期金额 | 已过到期日且未结清 | 同上 |
| 当月回款 | 本月内到账金额 | 同上 |
| 月度趋势 | 近 12 月折线 | `report:dashboard` |
| 账龄环图 | 未到期 / 0-30 / 31-90 / >90 占比 | `report:aging` |

数据范围跟着你的角色走：销售看自己的、主管看部门的、财务/高管看全公司。

## 3. 客户管理

路径：`#/customers`

### 3.1 新建客户

1. 列表页右上角点 **「+ 新建客户」**。
2. 必填项：客户名称、客户类型（个人 / 企业）、级别（A/B/C/D）。
3. 可选：USCC（统一社会信用代码）、地址、联系人占位、备注。
4. 提交后进入客户详情页。**客户名称 / USCC 重复会查重**，可选择「合并」或「使用同名」。

### 3.2 列表搜索

- 顶部搜索栏支持关键字（按名称模糊匹配）。
- 高级筛选：按类型 / 级别 / 创建日期范围。
- **看不到别人创建的客户是预期行为**（数据范围限制）。

### 3.3 详情页 4 个 Tab

进入 `#/customers/:id` 后顶部按钮区有「编辑 / 停用 / 删除（软删）」，下方 4 个 Tab：

| Tab | 你能做什么 |
| --- | --- |
| 基本信息 | 看客户档案、点「编辑」改字段（关键字段变更会写变更记录） |
| 联系人 | + 新增联系人；勾选「设为主联系人」；电话/邮箱自动加密存库 |
| 关联合同 | 该客户名下所有合同列表，点行可跳到合同详情 |
| 变更记录 | 谁、什么时候、改了哪个字段、改前改后 |

### 3.4 客户合并（去重）

发现是同一家公司的两条客户记录，点详情页右上「更多 → 合并到…」，选择 **保留**的客户记录，**被合并**记录下的合同/回款会迁移过去。**该操作不可逆**，请仔细确认。

### 3.5 软删除与禁用

- **删除（软删除）**：仅状态为「未启用 / 无业务」时可删；进入回收站，可还原。
- **停用**：保留客户和历史数据，但不再用于新建合同。

## 4. 合同管理

路径：`#/contracts`

### 4.1 新建合同

1. 列表页右上角 **「+ 新建合同」**。
2. 必填：合同名称、类型（销售 / 采购）、关联客户、金额、签订日、履约开始 / 结束、提醒提前天数（默认 30）。
3. 提交后进入合同详情，**初始状态为「草稿 DRAFT」**。

### 4.2 状态流转（重要）

合同有 5 个状态，**只能按下图迁移**：

```
DRAFT ─────▶ EFFECTIVE ─────▶ COMPLETED
   │             │
   ▼             ▼
TERMINATED   TERMINATED / EXPIRED（系统自动）
```

| 操作 | 入口 | 何时能做 |
| --- | --- | --- |
| 提交履行 | 详情页 → 状态流转 → 「履行中」 | 仅 DRAFT 可点 |
| 完成 | 状态流转 → 「已完成」 | 仅 EFFECTIVE 可点 |
| 终止 | 状态流转 → 「已终止」 | DRAFT / EFFECTIVE 都可 |
| 过期 | 系统每天 08:00 自动 | 履约结束日 +1 自动 EXPIRED |

非法跳转（比如 DRAFT 直接到 COMPLETED）会被系统拒绝并报错 `CT-002 合同状态不合法`。

### 4.3 上传附件（UC-03-05）

合同详情页 → **「附件」Tab**：

- 点 **「上传附件」**按钮选文件。
- 限制：**单文件 ≤ 50MB，单合同最多 20 个**（可由管理员在「系统参数」调整 `contract.attachment.max_count`）。
- 允许扩展名：`pdf / doc / docx / xls / xlsx / ppt / pptx / jpg / jpeg / png / zip / rar / txt`。
- 上传完成后行内有 **「预览/下载」** 与 **「删除」**。
- 失败会弹错误：
  - `FL-003 文件大小超出限制` ← 文件超过 50MB
  - `CT-005 附件类型不允许` ← 扩展名不在白名单
  - `CT-004 附件数量已达上限` ← 该合同已传到上限

### 4.4 备注与变更记录

- **备注 Tab**：销售主管可对合同加备注（销售也能看到），用于沟通要点。
- **时间线 Tab**：自动汇总状态流转、关键字段修改的历史，**不可手工删**。

### 4.5 删除合同（软删）

- 详情页右上「删除」。**仅 DRAFT / TERMINATED / EXPIRED 可删**，履行中的合同需先终止。
- 软删进回收站，**带级联**：附件、变更记录、回款计划、回款记录都跟着进回收站。

## 5. 回款管理

路径：`#/payments`，包含「回款记录」「回款计划」两个子页签。

### 5.1 排回款计划

1. 进入合同详情页 → **「回款计划」Tab**。
2. 点 **「批量生成」**，输入：
   - 首期日期（默认合同签订日）
   - 期数（如 12）
   - 频率（月度 / 季度 / 半年 / 年）
3. 系统按等额分摊生成 N 期，可在生成后**手工微调**单期金额或日期。
4. **合同状态必须是 EFFECTIVE 才能生成计划**，DRAFT 会拒绝。

也可以点 **「+ 新增计划」** 单独加一期。

### 5.2 登记实际回款（自动核销）

`#/payments` 列表页右上「+ 新增回款」：

| 字段 | 说明 |
| --- | --- |
| 关联合同 | 必填，下拉选 |
| 到账日期 | 客户钱真正到的日子 |
| 金额 | 本笔到账金额 |
| 付款人 | 客户实际打钱的主体（可与客户名不同） |
| 凭证号 | 银行流水号、发票号等（加密存储） |
| 关联计划（可选） | 不填则按 **FIFO** 自动核销最早未结清那几期 |

提交后系统：

1. 写入 `payment_record`；
2. 自动 **从计划日期最早开始** 扫平：足额扫平 → 计划状态 SETTLED；不够扫一期 → 该期 PARTIAL。
3. 月度趋势、账龄、Dashboard 全部刷新。

**示例**：3 期 ×10000 元，登记一笔 25000 元 → 第 1、2 期 SETTLED 各 10000，第 3 期 PARTIAL 已核销 5000 / 未核销 5000。

### 5.3 红冲（错账纠正）

发现登记错了，**不能直接删**回款记录（违反财务原则），用「红冲」：

1. `#/payments` 列表点错的那行 **「红冲」**。
2. 输入红冲金额（默认全额）和原因。
3. 系统：
   - 生成一条状态为 `RED` 的负数记录；
   - 把原记录改成 `REVERSED`；
   - 撤销在各计划上的核销（计划回到 PENDING / PARTIAL）。

需要 `payment:red` 权限（默认财务有）。

### 5.4 手工核销

如果某笔到账系统自动核销错了对应期，财务可在记录详情点 **「手工核销」**，重新指定要核销到哪几期。需要 `payment:settle` 权限。

### 5.5 Excel 批量导入

`#/payments` 右上 **「导入」**：

1. 下载模板（按合同编号 + 到账日 + 金额 + 付款人 + 凭证号）。
2. 填好上传，系统逐行校验：
   - 合同不存在 / 编号错 → 该行失败，不影响其他
   - 日期格式错（要 `yyyy-MM-dd`）→ 失败
   - 金额非数字 → 失败
3. 结果页显示成功 N 条 / 失败 M 条 + 失败原因。

需要 `payment:import` 权限。

## 6. 报表与账龄

### 6.1 账龄分析

路径：`#/payments/aging`

四桶展示当前未结清金额：

| 桶 | 含义 |
| --- | --- |
| UNDUE | 未到期 |
| 0-30 | 已逾期 0-30 天 |
| 31-90 | 已逾期 31-90 天 |
| OVER_90 | 逾期超 90 天 |

点任一桶的「钻取」可看明细——具体哪些计划在这个桶里。

### 6.2 报表中心

路径：`#/reports`，常用报表：

| 报表 | 内容 | 导出格式 |
| --- | --- | --- |
| 月度趋势 | 近 N 月合同 / 回款 / 应收金额折线 | Excel |
| TOP 客户 | 按已回款 / 待回款 / 合同额 TOP N | Excel |
| 我的待办 | 个人未完成项（应跟进合同、待登记回款等） | — |

需要 `report:export` 权限才能导出。

## 7. 通知中心

路径：`#/notifications`，顶部铃铛图标显示未读数量。

### 7.1 站内信场景

| 场景 | 何时触发 | 默认接收人 |
| --- | --- | --- |
| `CONTRACT_DUE` | 合同到期前 30 天（每天 09:00） | 合同负责人 + 部门主管 |
| `PAYMENT_DUE_SOON` | 计划日前 7 天（每天 09:30） | 合同负责人 |
| `PAYMENT_OVERDUE` | 已逾期，每 3 天重复 | 合同负责人 + 财务 |

提前天数与重复周期可由管理员在 [系统参数](./admin-manual.md#42-参数说明) 调整。

### 7.2 操作

- 点单条 → 标记已读。
- 「全部已读」一键清未读。
- 「归档」把不再需要的旧通知折叠。
- 「设置」：可关闭某些场景的提醒（自己关的，不影响别人）。

## 8. 软删除与回收站

### 8.1 删除策略

CRMS 默认所有删除都是 **软删除**：

| 业务 | 谁能软删 | 进哪种回收站 |
| --- | --- | --- |
| 客户 | 销售（自己的）/ 系统管理员 | `CUSTOMER` |
| 合同 | 销售（DRAFT）/ 系统管理员 | `CONTRACT`（带级联） |
| 回款记录 | 系统管理员 | `PAYMENT_RECORD`（不推荐，请用红冲） |

### 8.2 还原

- 业务用户**没有回收站权限**——找系统管理员到 `#/system/recycle` 还原。
- 还原后的记录回到原列表，状态保持原样。

### 8.3 硬删除（仅超管）

**不可逆**操作，仅 R05 系统管理员可做，且需要：
- 二次密码确认；
- 写入 `hard_delete_log`，含操作人、时间、原因、原快照。

普通用户**永远用不到**这个；误操作请走「还原」。

## 9. 常见错误码速查

按业务前缀分类（完整见 [DSS §6.5](./dss.md)）：

| 错误码 | 含义 | 你应该 |
| --- | --- | --- |
| `AUTH-401` | 未登录 / Token 过期 | 重新登录 |
| `AUTH-403` | 无权限 | 找管理员申请权限点 |
| `VAL-400` | 参数校验失败 | 看错误信息里说哪个字段 |
| `CU-001` | 客户不存在 | 客户已被删或 ID 错 |
| `CU-002` | USCC 已存在 | 走客户合并 |
| `CT-001` | 合同不存在 | 同上，或被删 |
| `CT-002` | 合同状态不合法 | 看 §4.2 状态机 |
| `CT-004` | 附件数量已达上限 | 删除旧附件或找管理员调系统参数 |
| `CT-005` | 附件类型不允许 | 改用白名单内的扩展名 |
| `PM-002` | 计划已结清 | 该期已 SETTLED，不可再操作 |
| `FL-002` | 文件上传失败 | 网络 / 存储问题，重试或找运维 |
| `FL-003` | 文件大小超出限制 | 单文件 ≤ 50MB |
| `SY-001` | 系统参数不存在 | 联系管理员检查参数表 |
| `SY-501` | 硬删除被拒 | 你没有该权限 |
| `SYS-500` | 系统错误 | 复制 traceId 给运维（在错误提示里） |

每条错误响应都带 `traceId`，**报问题时连同 traceId 一起发**，运维可在日志里精确定位。

## 10. 三个最常见的"我以为系统坏了"

| 现象 | 实际原因 |
| --- | --- |
| 菜单点了 404 | 你的角色没有该路由的权限点 |
| 列表是空的，但同事说他能看到 | 数据范围（SELF）限制：你只看到自己创建的 |
| 改了系统参数没生效 | 只有部分参数热生效（如附件上限、提醒天数）；个别需重启服务，问管理员 |
